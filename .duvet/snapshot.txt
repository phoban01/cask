SPECIFICATION: [Cask fleet objects](docs/spec/fleet.md)
  SECTION: [2. Resources](#2-resources)
    TEXT[!MUST,implementation,test]: Cask MUST serve its resources through the Kubernetes aggregation layer as an APIService.
    TEXT[!MUST,implementation,test]: Every fleet resource MUST be cluster-scoped.
    TEXT[!MUST,implementation,test,exception]: The extension server MUST be built on the generic server in k8s.io/apiserver.
    TEXT[!MUST,implementation,test,exception]: The extension server MUST delegate authentication and authorization to the local kube-apiserver.
    TEXT[!MUST,test,exception]: A client MUST be able to use kubectl, client-go informers, field selectors, and watch bookmarks against fleet resources without fleet-specific code.
    TEXT[!MUST,exception]: The extension server MUST report not ready until its storage is reachable.
    TEXT[!MUST,exception]: The extension server MUST report not ready until any pending migration import is complete.

  SECTION: [3. Storage model](#3-storage-model)
    TEXT[!MUST,implementation,test]: Each object MUST be stored in one cask register keyed by resource type and name.
    TEXT[!MUST,implementation,test]: Each resource type MUST have one index register that maps every object name to that object's latest sequence.
    TEXT[!MUST,implementation,implication,test]: An object's resourceVersion MUST be the index sequence at which the index register recorded that object version.
    TEXT[!MUST,implementation,implication,test]: Each index entry MUST record both the object register sequence and the index sequence at which the index register recorded it.
    TEXT[!MUST,implementation,implication,test]: A get MUST serve an object only once the index register records it.
    TEXT[!MUST,implementation,implication,test]: A get MUST read the object at the object register sequence that the index entry records.
    TEXT[!MUST,implementation,test]: A resourceVersion precondition MUST be checked against the index sequence of the object's index entry.
    TEXT[!MUST,implementation,test]: A list's resourceVersion MUST be the sequence of the index register.
    TEXT[!MUST,implementation,implication,test]: A mutation MUST write the object register before the index register.
    TEXT[!MUST,implementation,implication,test]: The index register MUST NOT record a sequence higher than the object register holds.
    TEXT[!MUST,implementation,implication,test]: When the index write of a mutation did not complete, the next index write for that object MUST record the object register's current sequence.
    TEXT[!MUST,implementation,implication,test]: A mutation whose object write committed MUST retry its index write when that index write loses a round or has an unknown outcome.
    TEXT[!MUST,implementation,test]: A read of the index register or an object register MUST retry when its round loses or has an unknown outcome.
    TEXT[!MUST,implementation,implication,test]: The extension server MUST reconcile the index register against the object registers at startup.
    TEXT[!MUST,implementation,test]: The extension server MUST reconcile the index register against the object registers at a fixed interval.
    TEXT[!MUST,implementation,implication,test]: A create MUST use a compare-and-set that requires the object register to be absent.
    TEXT[!MUST,implementation,implication,test]: A create MUST NOT write over a tombstone while the index register still names the deleted object.
    TEXT[!MUST,implementation,implication,test]: A create or an update MUST return the object version that it wrote, with the index sequence at which the index register recorded that version.
    TEXT[!MUST,implementation,implication,test]: A delete MUST return the index sequence at which the index register removed the name.
    TEXT[!MUST,implementation,test]: An update MUST use a compare-and-set on the resourceVersion the client supplied.
    TEXT[!MUST,implementation,test]: An update whose compare-and-set fails MUST return a conflict.
    TEXT[!MAY,implementation,implication,test]: A write that returned a conflict MAY have been committed.
    TEXT[!MUST,implementation,implication,test]: The extension server MUST re-read an object before it retries a write that returned a conflict.
    TEXT[!MUST,implementation,implication,test]: A retried write MUST be a compare-and-set, never a blind reapplication of a change.
    TEXT[!MUST,implementation,test]: A write that retries after an unknown outcome MUST wait longer before each retry, up to a fixed limit.
    TEXT[!MUST,implementation,test]: Every write MUST carry an operation identity that no other writer and no earlier process of the same writer has used.
    TEXT[!MUST,implementation,implication,test]: A delete MUST tombstone the object register before it removes the name from the index register.
    TEXT[!MUST]: An object value MUST NOT exceed 1 MiB.
    TEXT[!MAY,implementation,implication,test]: Two proposers MAY choose the same ballot.
    TEXT[!MUST,implementation,implication,test]: An acceptor MUST promise a ballot only if the ballot is higher than every ballot that the acceptor has promised.

  SECTION: [4. List and watch](#4-list-and-watch)
    TEXT[!MUST,implementation,test,exception]: A list MUST return every object that the index register names at the index sequence the list reports.
    TEXT[!MUST,implementation,implication,test,exception]: A watch from a resourceVersion MUST deliver every index change after that version, in order, with no gaps.
    TEXT[!MUST,implementation,test,exception]: A watch whose start version is compacted MUST end with 410 Gone.
    TEXT[!MUST,implementation,implication,test,exception]: Each watch event MUST carry the object at the sequence the index recorded.
    TEXT[!MUST,implementation,implication,test]: Every resourceVersion that a get, a list, or a watch event reports MUST be an index sequence.
    TEXT[!MUST,implementation,implication,test]: A watch that resumes from the resourceVersion of any event MUST NOT skip or replay a change.
    TEXT[!MUST,implementation,implication,test]: A watch MUST report the deletion of an object and the creation of a new object with the same name as separate events.
    TEXT[!SHOULD,exception]: Watch events SHOULD be pushed from the index register's change feed rather than polled.

  SECTION: [5. Claims and fencing](#5-claims-and-fencing)
    TEXT[!MUST,implementation]: Binding a claim to an object MUST be the acquisition of that object's cask lock under the claim's session.
    TEXT[!MUST,implementation,implication,test]: At most one claim MUST be Bound to an object at the object's current fence.
    TEXT[!MUST,implementation,implication,test]: Every successful acquisition MUST mint a fence strictly greater than every fence previously minted for that object.
    TEXT[!MUST,implementation,implication,test]: An acquire by the session that already holds the lock MUST return the current fence and MUST NOT mint a new one.
    TEXT[!MUST,implementation,test]: A Bound claim MUST carry its fence in its status.
    TEXT[!MUST]: A controller MUST include the claim's fence in every effect it applies for that object.
    TEXT[!MUST,implementation,implication,test]: A receiver MUST reject an effect whose fence is lower than the highest fence it has accepted for that object.
    TEXT[!MUST,implementation,test]: A status write MUST NOT lower an advertised fence.
    TEXT[!MUST,implementation,implication,test]: A Device status MUST keep in its lastFence field the highest fence that the Device has advertised.
    TEXT[!MUST,implementation,implication,test]: A write to a Device MUST NOT lower its lastFence.
    TEXT[!MUST,implementation,implication,test]: Deleting a claim MUST NOT complete before the lastFence of its Device is at least the claim's fence.
    TEXT[!MUST,implementation]: A controller MUST reconcile only claims whose status names its own cluster.
    TEXT[!MUST,implementation,implication,test]: When a claim's session lapses, the controller MUST set the claim to Lost.
    TEXT[!MUST]: A controller MUST NOT apply an effect for a claim it knows to be Lost.
    TEXT[!MUST,implementation,implication,test]: Deleting a Bound claim MUST release the object's lock.
    TEXT[!MAY]: Fencing rejects effects that are older than the newest holder's fence; it MAY accept an expired holder's effect while no successor exists.

  SECTION: [6. Membership](#6-membership)
    TEXT[!MUST]: A fleet MUST start from exactly one founding member.
    TEXT[!MUST]: Every member MUST be either a voter or a participant.
    TEXT[!MUST]: A participant MUST be able to read, watch, and propose without holding register replicas.
    TEXT[!MUST]: Only voters MUST hold register replicas.
    TEXT[!MUST,implementation,implication,test]: The voter set MUST change only by joint-consensus reconfiguration of the roster.
    TEXT[!MUST,implementation,implication,test]: A core change MUST carry every data register forward to the new core before it releases the old core.
    TEXT[!MUST,implementation,implication,test]: During a core change, a data write MUST reach a quorum of both the old and the new core.
    TEXT[!MUST,implementation,implication,test]: A voter MUST reject a data write that names an older core configuration than the roster value it has accepted.
    TEXT[!MUST,implementation,test]: A voter MUST NOT list its data keys while a data write that passed its fence is still in progress.
    TEXT[!MUST,implementation,implication,test]: A core change MUST list data keys only on old voters that have accepted the joint roster value.
    TEXT[!MUST,implementation,test]: A core change MUST finish while a majority of the old core and a majority of the new core answer.
    TEXT[!MUST,implementation,implication,test]: A resumed core change MUST carry every data register that it did not carry under the same joint configuration.
    TEXT[!MUST,implementation,test]: The extension server MUST answer a data write that a voter rejected as stale with a retryable status.
    TEXT[!MUST,implementation,test]: A roster read that loses its round MUST retry after a jittered backoff, up to a fixed number of attempts.
    TEXT[!MUST]: An operator MUST NOT grow the voter set by restarting members with a longer static peer list.
    TEXT[!MUST,implementation,test]: The voter count MUST be odd.
    TEXT[!MUST,implementation,test]: The voter count MUST NOT exceed five.
    TEXT[!MUST,implementation,test]: A promote or demote request MUST apply its whole list of member ids in one core change.
    TEXT[!MUST,implementation,test]: A promote request MUST name only participants.
    TEXT[!MUST,implementation,test]: A demote request MUST name only voters.
    TEXT[!SHOULD]: The voter set SHOULD contain at most one voter per management cluster once three or more clusters exist.
    TEXT[!MUST]: The founding member MUST remain available until the voter set has grown to three.
    TEXT[!MUST,implementation,test]: The extension server MUST join the fleet through the dynamic roster path.
    TEXT[!MUST]: A new member MUST be able to join with a seed address and a minted certificate and nothing else.

  SECTION: [7. Migration](#7-migration)
    TEXT[!MUST,implementation,test]: The extension server MUST serve the same API group, version, and kinds that the CRD served.
    TEXT[!MUST,implementation,test,exception]: The migration MUST preserve each object's uid.
    TEXT[!MUST,implementation,test,exception]: The migration MUST preserve each object's creationTimestamp.
    TEXT[!MUST,exception]: Writers MUST be frozen from the start of the export until the APIService is available.
    TEXT[!MUST,exception]: The APIService MUST NOT become available before the import has completed.
    TEXT[!MUST,exception]: The APIService MUST NOT become available while any imported object that other objects reference by ownerReference is missing.
    TEXT[!MUST,exception]: The initial index sequence for each resource type MUST be greater than the source etcd revision at export time.
    TEXT[!MUST,implementation,implication,test]: The fences that the export records for a Device MUST include the lastFence in its status.
    TEXT[!MUST,implementation,implication,test]: The import MUST NOT seed an object's lock at a fence below the highest fence that the export recorded for that object.
    TEXT[!MUST,implementation,implication,test]: The import MUST restore a Bound claim as Bound only when that claim alone holds the highest fence that the export recorded for its object.
    TEXT[!MUST,implementation,implication,test]: The import MUST write a Bound claim as Lost when it does not restore that claim as Bound.
    TEXT[!MUST,implementation,implication,test]: The import MUST grant a restored claim's session and seed its lock before it writes the claim.
    TEXT[!MUST,implementation,test]: The import MUST grant a restored claim's session for the claim's TTL plus an import grace.
    TEXT[!MUST,implementation,test]: The import MUST renew each restored claim's session after it writes the import marker.
    TEXT[!MUST,exception]: A continuous export of all fleet objects MUST run from the first day of phase one.
    TEXT[!MUST,exception]: The cutover MUST be rehearsed on a copy of the management cluster before it runs on the real one.

  SECTION: [8. Security](#8-security)
    TEXT[!MUST,implementation,test]: Consensus traffic between members MUST use mutual TLS.
    TEXT[!MUST,exception]: The extension server MUST serve HTTPS with a certificate the kube-apiserver can verify.
    TEXT[!MUST,implementation,test,exception]: The cask client API and control endpoints MUST NOT be reachable outside the pod without authentication.

  SECTION: [9. Operations](#9-operations)
    TEXT[!MUST,implementation,exception]: Every voter MUST persist its acceptor state to a durable volume.
    TEXT[!MUST,exception]: A rolling upgrade MUST keep a majority of voters available at all times.
    TEXT[!MUST,exception]: A majority-loss recovery procedure MUST be documented.
    TEXT[!MUST,exception]: The majority-loss recovery procedure MUST be rehearsed before phase two.
    TEXT[!MUST,exception]: Cask MUST expose a health signal for quorum state.
    TEXT[!MUST,exception]: Cask MUST expose counters for lease expiries and for rejected fence regressions.
